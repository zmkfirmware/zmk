## 概览 / Overview

`LED Matrix` 是一个位于 ZMK 渲染层之上的 RGB 控制器。它不是对单一硬件类型的命名，而是一个把多种输入源统一渲染到逻辑 LED 空间的子系统：基础 profile、layer color、independent LED container、Battery/USB/BLE/HID 状态叠加都由它统一仲裁。

`LED Matrix` is an RGB controller that sits above the hardware backend. It is not tied to a single LED family; instead, it renders multiple sources into one logical LED space: base profiles, layer colors, independent LED containers, and Battery/USB/BLE/HID status overlays.

- `RGB underglow` 面向可寻址灯带，直接使用 `led_strip` 驱动。
- `Backlight` 面向单色并联背光，主要控制亮度。
- `LED Matrix` 面向“逻辑 RGB 矩阵”，可以使用 Zephyr `led` API backend，也可以直接使用 `led_strip` backend。

- `RGB underglow` targets addressable strips and talks directly to `led_strip` drivers.
- `Backlight` targets single-color parallel LEDs and mainly controls brightness.
- `LED Matrix` targets a logical RGB matrix and can use either a Zephyr `led` backend or a direct `led_strip` backend.

`led-driver = "matrix"` 表示 LED Matrix 通过 Zephyr `led` API 输出，典型目标可以是矩阵驱动芯片，也可以是 `led_composite` 这样的聚合器。`led-driver = "strip"` 表示 LED Matrix 直接输出到 Zephyr `led_strip` API。

`led-driver = "matrix"` means LED Matrix writes through the Zephyr `led` API. The target can be a matrix driver chip or an aggregator such as `led_composite`. `led-driver = "strip"` means LED Matrix writes directly to the Zephyr `led_strip` API.

`led_composite` 本身不是渲染器，而是一个“扁平 RGB channel 空间”的 backend 适配层。它可以把多个 `led-device` 和 `led-strip-device` 子设备拼成一个连续的通道空间，再由 `zmk,led-matrix` 通过 `channel-indexes` 做逻辑映射。

`led_composite` is not a renderer. It is a backend adapter that exposes a single flattened RGB channel space built from multiple `led-device` and `led-strip-device` children, which `zmk,led-matrix` can then map with `channel-indexes`.

- `CONFIG_ZMK_LED_MATRIX_USES_LED_API` 与 `CONFIG_ZMK_LED_MATRIX_USES_LED_STRIP_API` 是隐藏选项，由 `/chosen { zmk,led-matrix = ...; }` 指向节点的 `led-driver` 自动计算。
- 如果 `led-driver = "matrix"`，`CONFIG_ZMK_LED_MATRIX` 会 `select LED`。
- 如果 `led-driver = "strip"`，`CONFIG_ZMK_LED_MATRIX` 会 `select LED_STRIP`。

- `CONFIG_ZMK_LED_MATRIX_USES_LED_API` and `CONFIG_ZMK_LED_MATRIX_USES_LED_STRIP_API` are hidden helper options derived from the chosen `zmk,led-matrix` node.
- With `led-driver = "matrix"`, `CONFIG_ZMK_LED_MATRIX` selects `LED`.
- With `led-driver = "strip"`, `CONFIG_ZMK_LED_MATRIX` selects `LED_STRIP`.

The constraints are just as important:

- `layer-leds` 省略时，目标 LED 默认来自 `matrix-led-grid` 的遍历顺序。

- When `matrix-led-grid` is present, `independent-leds` must not also appear in that grid.

## `led_composite`

### 核心概念 / Core concept

`zmk,led-composite` 使用 child node 把多个 backend 拼成一个连续的 RGB channel 空间。每个 child 都声明自己在这个扁平空间中的起始位置和长度。

`zmk,led-composite` uses child nodes to flatten multiple backends into one continuous RGB channel space. Each child declares its offset and length inside that flattened space.

| 属性 / Property    | 必填 / Required     | 说明 / Meaning                                                                                                                 |
| ------------------ | ------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `led-device`       | 二选一 / one of two | 使用 Zephyr `led` API 的 child backend / Child backend that exposes the Zephyr `led` API                                       |
| `led-strip-device` | 二选一 / one of two | 使用 Zephyr `led_strip` API 的 child backend / Child backend that exposes the Zephyr `led_strip` API                           |
| `channel-offset`   | 是 / Yes            | child 在扁平通道空间中的起始位置 / Start offset in the flattened channel space                                                 |
| `channel-count`    | 是 / Yes            | child 暴露的可写 RGB 通道数；strip child 必须是 3 的倍数 / Writable RGB channel count; strip children must use a multiple of 3 |
| `ext-power-device` | 否 / No             | strip child 可选共享电源控制器 / Optional shared power controller for strip children                                           |

约束如下：

The constraints are:

- 每个 child 必须定义且只定义 `led-device` 或 `led-strip-device` 之一。
- 所有 child range 必须从 `0` 开始，按升序连续排列，不能重叠也不能留空洞。
- 多个 strip child 如果使用 `ext-power-device`，必须共享同一个设备。

- Each child must define exactly one of `led-device` or `led-strip-device`.
- Child ranges must start at `0`, be declared in ascending order, and remain contiguous with no overlaps or holes.
- When multiple strip children use `ext-power-device`, they must share the same device.

### public API 与 capability 宏 / public API and capability macros

## 常见错误 / Common Errors

以下问题都能在源码校验或现有测试中找到对应案例：

These errors are all enforced either by runtime validation in the source or by existing tests:

- `CONFIG_ZMK_LED_MATRIX=y` 但没有 `/chosen { zmk,led-matrix = ...; }`
  原因 / Why: 子系统找不到主控制节点。
  修正 / Fix: 在根节点 `chosen` 中设置 `zmk,led-matrix = &led_matrix;`

- `led-driver = "matrix"` 但缺少 `led-device`，或 `led-driver = "strip"` 但缺少 `led-strip-device`
  原因 / Why: backend 设备与所选驱动类型不匹配。
  修正 / Fix: 按 driver 类型提供正确的 phandle。

- `zmk,led-matrix` 既没有 profile，也没有 independent child、layer color、status zone
  原因 / Why: 没有任何可渲染来源。
  修正 / Fix: 至少提供一种 renderable source。

- `channel-indexes` 长度不是 `led-count * 3`
  原因 / Why: 逻辑 RGB 通道映射表不完整。
  修正 / Fix: 保证每个逻辑 LED 都提供 3 个通道索引。

- 在不支持 `write_channels` 的 backend 上使用 `channel-indexes` 或 `output-channel-count`
  原因 / Why: 这些属性只适用于 write-channels backend。
  修正 / Fix: 改用支持 `write_channels` 的 backend，或者使用 `led-indexes`。

- `keypress`、`ripple`、`rain` renderer 缺少 `matrix-led-grid`
  原因 / Why: 位置驱动效果需要 RC 网格。
  修正 / Fix: 提供与当前 kscan 行列一致的 `matrix-led-grid`。

- layer color 未设置 `layer-leds`，但同时缺少 `matrix-led-grid`
  原因 / Why: 默认目标 LED 集合无法推导。
  修正 / Fix: 补 `matrix-led-grid`，或为该 layer color 显式设置 `layer-leds`。

- independent child 的 `independent-id` 重复或出现空洞
  原因 / Why: runtime 会按连续编号管理独立容器。
  修正 / Fix: 使用从 `0` 开始、连续且唯一的 `independent-id`。

- `led_composite` child 同时定义了 `led-device` 和 `led-strip-device`，或者两者都没定义
  原因 / Why: child 类型无法唯一确定。
  修正 / Fix: 每个 child 严格二选一。

- `led_composite` child range 重叠、未从 `0` 开始、或中间有 gap
  原因 / Why: composite 要求一个连续的扁平通道空间。
  修正 / Fix: 让 `channel-offset`/`channel-count` 从 `0` 开始连续拼接。

- strip child 的 `channel-count` 不是 3 的倍数，或多个 strip child 使用了不同的 `ext-power-device`
  原因 / Why: strip backend 以 RGB 像素为单位，电源策略也要求共享。
  修正 / Fix: 保持 `channel-count % 3 == 0`，并统一 `ext-power-device`。
