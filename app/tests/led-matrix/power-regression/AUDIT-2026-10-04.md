# LED Matrix 熄灯功耗审计

日期：2026-10-04（Asia/Shanghai）。目标：保留 BLE 连接和正常按键唤醒，检查手动关闭、亮度归零、状态灯熄灭及电池闲置后是否消除 LED 引起的额外耗电。

**初次审计结论：不能认定所有场景均达到最低功耗。** 正常逻辑 OFF／AUTO_SUSPENDED 路径已有停止刷新和关闭受控电源的实现；本机已有故障回归通过。但审计另行复现了 composite 的关断误判、关断提前退出、持久化电源调用，以及状态颜色选择导致的无效周期刷新。部分板级默认策略也不满足本次目标。没有实机电流证据，不能给出整机最低电流或续航保证。

初次审计仅新增报告及独立构建目录内的复现材料，没有修改固件、公开 API、Devicetree、Kconfig、持久化格式、既有测试或快照。审计时 Git HEAD 为 `5b51501fe`，工作区包含大量用户未提交文件；不能以该提交号单独代表被审计固件。

**记录范围：第 1–5 节保留修复前的发现、配置和测试证据。** 其中“当前”、源码行号、配置哈希及复现结果均对应初次审计快照，不作为修复后代码的验证结果；后续源码修改可能使链接行号移动。第 6 节跟踪本轮修复契约和待完成的主线验证。

## 1. 按优先级排列的发现

### F1 · P1：composite 清屏失败可能被误记为已关断，后续 OFF 也跳过清屏

- **条件：** composite 含没有受控电源的 GPIO／PWM／strip child，清屏写入返回错误。纯无门控 composite 已通过 host 故障注入复现；混合后端存在相同覆盖不足，尚未单独动态复现。
- **原因：** [后端分类](/Users/elliotge/zmk/app/src/led_matrix.c:102) 将全部 composite 编译为支持 managed power；[composite 电源函数](/Users/elliotge/zmk/app/module/drivers/led/led_composite.c:711) 在实际无 managed capability 时直接返回成功。[上层软关断](/Users/elliotge/zmk/app/src/led_matrix/power.c:224) 据此设置全局关闭标记；[关断判断](/Users/elliotge/zmk/app/src/led_matrix/power.c:380) 未核对所有 child 的覆盖范围，[清屏收尾](/Users/elliotge/zmk/app/src/led_matrix/power.c:434) 因而吞掉清屏错误。下次 OFF 在同一函数的 `skip_flush` 分支跳过清屏。
- **证据：** 注入 `clear=-EIO`，实际返回 `0`，`reported powered down=1`；再次 OFF 后 clear 调用数仍为 `1`。这会阻止输出服务启动失败重试，失败前输出可能残留。
- **建议：** 区分“调用电源 API 成功”与“所有输出确实失能”。没有门控或仅部分门控时，保留未受控 child 的清屏错误并重试；只有确认所有输出已关断才能忽略清屏失败／跳过后续 clear。补纯无门控、混合及完整门控三类故障回归。

### F2 · P2：composite 第一个 child 关断失败，其他 child 和灯带电源不再尝试关闭

- **条件：** 第一个受控 matrix child 的 hard-off 或 soft blank 返回错误，后面还有可正常关断的设备或共享灯带电源。
- **原因：** [关断循环](/Users/elliotge/zmk/app/module/drivers/led/led_composite.c:724) 首次失败立即返回；共享电源关闭位于循环之后。
- **证据：** hard／soft 两种失败分别得到 `off calls=[1,0]`、`ext disable calls=0`、`strip rail=1`。若首个错误持续存在，当前三次重试仍无法到达后续设备；即使清屏成功，供电部分仍可能停留在非最低功耗状态。
- **建议：** 关断采用尽力完成策略：遍历所有 child 并尝试关闭共享电源，记录每个成功状态并返回首个／汇总错误，保留有界重试。恢复路径单独处理，不套用相同遍历规则。

### F3 · P2：Caps 已灭，未选中的动态亮灯颜色仍触发 50 ms 刷新

- **条件：** LED Matrix 仍 ACTIVE，HID 状态源有效，例如 `hid-timeout-ms=0`、Caps OFF、ON 色为 `LM_RAINBOW`、OFF 色为 `LM_BLACK`，其余输出静态黑色。
- **原因：** [HID 刷新判定](/Users/elliotge/zmk/app/src/led_matrix/core.c:1648) 同时检查 ON／OFF 两组颜色，不看当前 HID bit，也不跳过未配置的指示灯 zone；实际渲染只采用当前分支。USB／BLE 的相似判定也扫描所有状态颜色。
- **证据：** 提取生产判定、运行模式及 timer 函数的 host 复现中，Caps 输出选择 BLACK，仍连续产生 100 个模拟 50 ms 回调；USB NONE 黑色但未使用的 HID 色为虹彩、BLE CONNECTED 黑色但 OPEN 色为虹彩，也复现同样结果。
- **对照：** 静态 WHITE→BLACK、不随时间变化的 PALETTE、逻辑 OFF、idle suspended、sleep suspended、输出同步失败均不启动 timer；ACTIVE→OFF 会停止已启动的 timer。因此不能说“显式关灯后仍必然刷新”。被检查板的默认 Caps ON 色为静态色，本项是可配置触发的问题。
- **影响：** 多余 CPU 唤醒／渲染计算。相同帧有缓存去重，**不能据此声称每 50 ms 都发生总线写入**。
- **建议：** 按当前状态选取颜色分支，仅检查实际配置且生效的 zone；保留 BLE pairing 闪烁所需 tick。Battery 的桶选择及覆盖关系也按实际输出核对。补未使用动态分支与真实动态输出的正反对照。

### F4 · P2：composite 临时关断／恢复使用持久化外电源接口

- **条件：** composite strip child 绑定真实 `zmk,ext-power-generic`，且启用 settings。
- **原因：** [composite OFF](/Users/elliotge/zmk/app/module/drivers/led/led_composite.c:746)／[ON](/Users/elliotge/zmk/app/module/drivers/led/led_composite.c:769) 调用 `ext_power_disable/enable`；[generic 实现](/Users/elliotge/zmk/app/src/ext_power_generic.c:100) 更新持久状态并请求 settings save。直接 strip 路径已使用 `*_runtime`。
- **证据：** 一次关闭加恢复产生 `persistent API=2`、`runtime API=0`、`settings save requests=2`。这是保存请求次数；实际 Flash 写入会受 debounce 和 settings 后端去重影响，不能等同于两次物理写入。
- **建议：** 临时 LED 电源协调改用 runtime API，验证自动熄灯、状态提示和恢复均不改变持久化开关，也不创建额外保存工作。

### F5 · P2／配置差距：corne54v3 与 bmk4SGK 没有启用闲置自动熄灯

- 本次 fresh 配置确认 corne54v3 左右、bmk4SGK 的 `CONFIG_ZMK_LED_MATRIX_AUTO_OFF_IDLE=n`。全局 activity idle 阈值存在，不代表 LED 会自动暂停。
- corne54v3 默认 `ON_START=n`，但用户打开 LED 后，15 s 闲置不会自动关闭基础灯效和灯带电源。bmk4SGK 的 HID timeout 为 0，Caps／Scroll 持续为 ON 时，30 s 闲置仍保持亮灯；锁定状态变 OFF 时静态 GPIO 正常灭灯，本项不应描述成“GPIO 灭灯后仍周期渲染”。
- **建议：** 若执行本次闲置熄灯目标，在这些板启用 auto-off，并验证持久 HID 状态唤醒后恢复及提示超时后再次关闭。此报告未改变该产品策略。

### F6 · P2／目标差距：corne54 两代默认 1 小时后深睡

- corne54 与 corne54v3 左右均启用 `ZMK_SLEEP=y`，阈值 `3600000 ms`。[活动管理](/Users/elliotge/zmk/app/src/activity.c:88) 在电池闲置超时后挂起设备并调用 `sys_poweroff()`，不满足无限期保留 BLE 连接的目标。
- **建议：** 后续若以保留连接为产品要求，关闭这些板的 deep sleep，保留 LED／显示 idle 控制；不能用关机电流作为保留 BLE 时的功耗验收结果。

F1、F2、F4 是通用 composite 能力的缺陷；本次六类板的默认 LED backend 均为直接 IS31、strip、GPIO 或 PWM，未选 composite，因此不要将这些故障误报成所有默认板必现。

## 2. 四条熄灯路径及已确认行为

| 场景 | 当前代码行为 | 检查结论与边界 |
| --- | --- | --- |
| `LM_OFF` | `state.on=false`；清状态、涟漪和按键余辉；立即同步停止 tick；异步清屏和电源关闭 | 正常路径完整；API 返回值是 settings 调度结果，不是硬件关断完成凭据。F1/F2 是错误场景例外 |
| 全局亮度设为 0 | 直接调用 `zmk_led_matrix_off()` | 与 LM_OFF 一致；不是仍 ACTIVE 的零亮度模式 |
| OFF／auto-suspended 时临时状态提示结束 | 清除 transient 和 force-show，再停止 tick 并请求关闭电源 | 有明确收尾；真实 Zephyr 事件交错尚未执行集成验收 |
| ACTIVE 中 Caps／Num 等变 OFF | 渲染相应 OFF 颜色，恢复低优先级输出；不会自动设置 `state.on=false` | 静态 GPIO 黑色可无周期刷新；动态颜色误判见 F3；底层有静态／动画灯效时仍可继续发光 |
| 电池 idle 且 auto-off=y | 保留用户开关状态，进入 AUTO_SUSPENDED，清临时状态、停 tick、清屏／关电 | 按键活动恢复；USB 供电阻止 idle auto-off；已 idle 时拔 USB 会立即重新应用电池策略 |

主要入口：[API](/Users/elliotge/zmk/app/src/led_matrix/api.c:231)、[异步暂停](/Users/elliotge/zmk/app/src/led_matrix/power.c:507)、[提示结束](/Users/elliotge/zmk/app/src/led_matrix/power.c:764)、[idle](/Users/elliotge/zmk/app/src/led_matrix/power.c:625)、[USB 事件](/Users/elliotge/zmk/app/src/led_matrix/status.c:203)。

**逻辑启用但全黑不等于已经关电。** [电源目标](/Users/elliotge/zmk/app/src/led_matrix/power.c:319) 依据运行模式是否允许渲染，不检查最终输出是否持续全黑。静态黑色、状态关闭或按键余辉结束可以让 tick 停止，但直接 IS31／strip 在 ACTIVE 下仍保持供电。这符合现有运行模式设计，却不能作为“任何可见熄灯都达到最低功耗”的保证。若后续扩展，应为“无输出需求且无即将发生的动画变化”设计可唤醒门控；不要对呼吸／闪烁的瞬时黑帧逐帧断电。

已确认的资源收尾：

- [tick](/Users/elliotge/zmk/app/src/led_matrix/render.c:870) 为 50 ms，仅渲染允许且需要时间变化时启动；OFF／AUTO_SUSPENDED／SLEEP_SUSPENDED 阻断。
- [输出重试](/Users/elliotge/zmk/app/src/led_matrix/render.c:893) 最多追加 100／500／2000 ms 三次重试；成功取消，耗尽后等待新请求，不无限轮询。新目标使旧重试失效。
- [sleep 同步收尾](/Users/elliotge/zmk/app/src/led_matrix/power.c:519) 取消并等待 retry／render work；普通 OFF 是异步收尾，允许已经排队的工作完成一次检查，不等于绝对零回调。
- 手动 LED 配置变更保留必要的一次 settings debounce 工作；numpad／corne／bmk4SGK 为 60 s，numpadv2／n52test 为 5 s。这是预期持久化，不是持续刷新泄漏，测量稳定基线应覆盖其结束时间。
- 默认允许 idle 后 30 min 内自动状态事件短暂唤灯，n52test 窗口为 0。重复状态事件可能延长提示截止时间；提示结束后才比较 OFF 基线。纯电池电量事件在 OFF 时只更新快照。

## 4. 底层与整机功耗边界

- **IS31：** [公共关断](/Users/elliotge/zmk/app/module/drivers/led/is31/power.c:126) 在 I²C 软件 shutdown 失败时仍尝试 SDB；GPIO 成功才承认硬关断。SDB 是芯片 shutdown，不是切断 VCC。恢复初始化及页缓存已有故障回归。
- **GPIO／PWM：** GPIO OFF 写不活动电平；[nRF PWM](/Users/elliotge/zmk/zephyr/drivers/pwm/pwm_nrfx.c:268) 对零占空比设静态电平，所有通道均不需要 PWM 时调用停止流程。不能单因没有 PM suspend 就认定 PWM 持续运行；共享 PWM 通道仍有其他用途时也不能直接关闭整个实例。
- **SPI／I²C：** WS2812 提交黑帧只写 SPI，灯珠是否掉电取决于外电源控制。[SPIM 事务结束](/Users/elliotge/zmk/zephyr/drivers/spi/spi_nrfx_spim.c:144) 会执行 runtime put；完整 uninit／sleep pinctrl 位于 suspend 路径。本次配置确认 corne54／v3 未启用 runtime PM，numpadv2／n52test 已启用；停止写入不能直接证明控制器已进入最深挂起。禁用 runtime PM 时驱动仍有释放时钟的路径，不能只凭配置断言高电流；需要测量，也不能由 LED 擅自 suspend 共用总线。
- **显示：** corne54v3 LS0XX 没有 `disp-en-gpios`，[驱动 blank](/Users/elliotge/zmk/zephyr/drivers/display/ls0xx.c:92) 返回 `-ENOTSUP`；[显示收尾](/Users/elliotge/zmk/app/src/display/main.c:77) 停 timer 但忽略返回值，只能证明停 LVGL 刷新。当前 DTS 也未启用 serial VCOM／EXTCOMIN，不能误报周期 VCOM SPI 仍在运行。numpad 的 ST75256 blank 会写 DISPLAY_OFF／SLEEP_IN。
- **共享电源：** DTS 能证明控制脚和软件所有者，不能证明 PCB 供电拓扑。尤其 numpad P0.12 EXT_POWER 不属于直接 IS31 的 SDB 关闭路径；不应在未查原理图时为 LED 擅自关闭可能共用的显示电源。
- **全局活动：** [activity timer](/Users/elliotge/zmk/app/src/activity.c:116) 在连接 idle 中仍每秒唤醒，是 LED 之外的既有开销。
- **电池采样：** [battery listener](/Users/elliotge/zmk/app/src/battery.c:166) 在 IDLE／SLEEP 停止电池 timer；不能把默认 60 s 间隔描述成 idle 中必然持续的负载。手动关灯但活动状态仍 ACTIVE 时才保留采样；n52test 没有 chosen battery 节点，不能只凭 REPORTING 配置推定存在采样。
- **BLE／日志：** 保留连接必有独立无线活动；numpad RTT／调试配置是测量变量。没有电流轨迹，不量化其贡献，也不推断熄灯等于整机停机。

### 剩余边界：composite 子 PWM 的极低非零颜色

composite 对 LED Matrix 暴露统一的 8 位通道输出，上层尚不读取每个 child 的最终亮度
量化方式。其 PWM child 把 RGB 最大分量通过 `value * 100 / 255` 转为百分比，因此最终
通道值为 1 或 2 时，实际 PWM 占空比为 0%，上层仍可能认为存在非零输出。

例如混合 IS31 与 PWM 的 composite 中，IS31 对应的逻辑颜色全黑，唯一非黑的 PWM
颜色为 `0x010000`、亮度为 100%：静态灯效可能保守地保持受控后端供电；呼吸灯效使用
相同极低颜色时，还可能保留周期 tick，尽管该 PWM 输出始终量化为零。本轮保留既有
公开 API 与 capability 位，没有为这一边界新增子设备输出映射查询。

该边界不影响所有逻辑 RGB 均为零、`LM_BLACK` 状态灯熄灭、显式关闭及闲置暂停的
关断路径；直连 scalar 后端已按百分比量化判断输出，也不受此 composite 边界影响。
它不改变 F1–F6 的修复结论，但不能据此声称“所有物理全黑场景均已达到最低功耗”。
